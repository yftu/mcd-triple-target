## 坑一：一段永远返回 0 的函数，静默地废掉了整个功能

**症状**：加了"低钠优选"功能，代码逻辑正确、测试全绿、输出格式正常，但功能完全不起作用。

**原因**：阈值按营养学常识设为 1400 mg，而真实数据里：

```
钠分布（160 条实测数据）
最小 1 ｜ P25 80 ｜ 中位 147 ｜ P75 705 ｜ 最大 1373 mg
```

**全表最大值 1373 mg < 阈值 1400 mg。** 这个函数永远不会返回非零值。

**最危险的地方**：它不报错。崩溃会告诉你哪里错了，静默失效让你以为自己是对的。

**修法**：别猜，用数据定。

```python
# ❌ 按"常识"
SODIUM_BASE = 1400# 依据：每日建议 2000mg 的七成

# ✅ 按真实分布（约 P70）
SODIUM_BASE = 600   # 实测：>600mg 占约 25%，>1400mg 占 0%
```

**教训**：越是"有依据"的数字，越容易让人停止思考。任何常识性阈值都要用真实数据回归验证。

## 坑二：加权评分被"套利"

**症状**：三目标配餐算法（热量 0.42 / 蛋白 0.36 / 预算 0.22），在增肌场景推荐出：

```
· 双层深海鳕鱼堡  485 kcal  蛋白 28 g  ¥22
· 冰美式小杯        15 kcal  蛋白  0 g  ¥10
· 圆筒冰淇淋        93 kcal  蛋白  2 g  ¥6
```

冰美式 + 冰淇淋占 22 块，只贡献 15 kcal 和 2 g 蛋白。

**这不是搜索 bug，是目标函数被套利**：

| 分项 | 零食组合的表现 |
|---|---|
| 热量项 | 冰淇淋热量低 → 拉低总热量 → **得分虚高** |
| 蛋白项 | 贡献 2 g，几乎无影响 |
| 预算项 | 便宜 → 拉低总花费 → **得分受益** |

单看每项都不算离谱，叠加后"低热量 + 便宜"就成了最优解。

**修法**：加与目标正交的约束

```python
# 蛋白能量占比惩罚（4 kcal/g 为标准参考）
protein_share = protein_total / (kcal_total / 4.0)
if protein_share < 0.55:
    bonus -= (0.55 - protein_share) * 45.0

# 低热量密度单品（饮料/冰品）占比惩罚
snack_kcal = sum(i.kcal for i in items if i.kcal <= 120)
if snack_kcal / kcal_total > 0.28:
    bonus -= (snack_kcal / kcal_total - 0.28) * 90.0
```

**验证**：修完后控卡场景结果完全不变（747 kcal / 蛋白 38 g），说明新约束没破坏原有方案——这才是合格的回归。

**教训**：加权归一化要防结构性套利，光调权重不够，必须加正交约束。

## 坑三：MCP 返回四层嵌套，不是 JSON

**症状**：写完标准 JSON 解析代码，发现 `data` 还是字符串；再解析，还是字符串。

真实结构：

```
Markdown 字段说明（含 {序号} 占位符）
  ↓ "## Original Response"
JSON 字符串
  ↓ obj["data"] 仍是字符串
toon 紧凑格式（160 条）
  ↓ 按列名 + 行记录
结构化数据
```

###坑 3a：不能直接取 JSON

第1 层说明文字里有 `{序号}` 占位符，`text[text.index("{"):]` 会命中错误片段。

```python
def unwrap_mcp_text(raw: str) -> str:
    """括号配对 + 转义感知，取能 loads 成功的最长片段"""
    text = raw.strip()
    marker = "## Original Response"
    idx = text.rfind(marker)
    if idx != -1:
        text = text[idx + len(marker):].strip()

    candidates, i, n = [], 0, len(text)
    while i < n:
        if text[i] == "{":
            depth, in_str, esc = 0, False, False
            for j in range(i, n):
                ch = text[j]
                if in_str:
                    if esc:          esc = False
                    elif ch == "\\": esc = True
                    elif ch == '"':  in_str = False
                    continue
                if ch == '"':     in_str = True
                elif ch == "{":   depth += 1
                elif ch == "}":
                    depth -= 1
                    if depth == 0:
                        candidates.append(text[i:j + 1])
                        i = j
                        break
            else:
                break
        i += 1

    best = ""
    for cand in candidates:
        try:
            json.loads(cand)
            if len(cand) > len(best):
                best = cand
        except Exception:
            continue
    return best or text
```

### 坑 3b：toon 不能直接 split

```
[160]{productName,nutritionDescription,energyKcal,protein,fat,carbohydrate,sodium,calcium}:
  猪柳麦满分,null,1288,308,16,16,24,781,213
  中薯条,null,1210,289,4,12,38,165,18
```

字段内容可能含逗号，`split(',')` 会错列：

```python
def _split_toon_row(line: str, ncols: int) -> list[str]:
    if line.count(",") == ncols - 1:
        return line.split(",")
    # 从右向左按列数反向定位分隔符
    parts, rest = [], line
    for _ in range(ncols - 1):
        pos = rest.rfind(",")
        if pos == -1:
            break
        parts.insert(0, rest[pos + 1:])
        rest = rest[:pos]
    return [rest] + parts
```

实测 160/160 条 100% 解析成功。
